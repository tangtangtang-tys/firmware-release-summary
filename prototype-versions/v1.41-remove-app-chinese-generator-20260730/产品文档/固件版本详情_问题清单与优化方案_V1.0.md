# 固件版本详情问题清单与优化方案 V1.0

## 1. 核查范围

- 当前发布版本、未发布版本、历史版本、回滚后版本、已下架版本。
- 功能点配置、APP 更新说明、历史功能集快照、发布记录、审批日志。
- 发布、回滚、下架、重新发布、版本编辑和文案修订的数据归属。

## 2. 核查结论

详情抽屉切换页签时只更新内部内容，抽屉保持同一实例，该交互已闭环。当前主要问题是业务数据口径不一致、状态表达不准确、发布过程被拆散，以及基础信息缺失或重复。

## 3. 问题与调整方案

| 优先级 | 问题 | 当前影响 | 调整方案 |
| --- | --- | --- | --- |
| P0 | 当前发布版本显示“功能点 0 项”，但新增与编辑规则要求固件必配功能自动加载 | 当前生效版本无法判断实际能力，发布快照与功能规则冲突 | 原型 Mock 为当前发布版本补齐发布时冻结的必配功能快照；真实历史空数据不反向补写，显示“该历史发布记录未采集功能点快照” |
| P0 | 发布记录只读取生效事件，审批驳回、审批失效、发布失败等过程只出现在审批或生命周期数据中 | 用户无法在版本详情内还原一次完整发布尝试 | 合并“发布记录”和“审批日志”为“发布与审批记录”，按流程聚合提交、审批、执行和结果 |
| P0 | 下架事件沿用正常发布模板，目标版本为空时会出现错误的版本箭头和动作名称 | 下架详情语义错误 | 发布、回滚、下架、重新发布分别使用独立文案和字段模板；下架显示被下架版本、原因和下架时间 |
| P0 | 详情顶部从“与该版本有关的第一条事件”读取提醒方式和生效时间 | 版本作为来源版本被替代或下架时，可能显示成别的动作时间 | 顶部只读取“该版本最近一次成功生效事件”；回滚、下架等退出当前状态的时间单独展示 |
| P0 | 审批卡片标题固定为“发布审批” | 回滚、下架审批会被错误标记为发布审批 | 标题按审批类型渲染为发布审批、回滚审批、下架审批；状态分别映射审批中、通过、驳回、失效 |
| P1 | 回滚后的版本状态显示“已撤销”，已下架版本显示“已下架” | “撤销”无法区分回滚和下架，状态术语不统一 | `withdrawn` 统一展示“已回滚”，`delisted` 展示“已下架”，并保留各自原因和时间 |
| P1 | 未发布版本仍展示 APP 提醒方式和生效时间 | 提醒策略尚未在发布时确定，却被呈现为既成事实 | 未发布版本显示“发布时配置”和“未生效”；历史版本展示“最近生效时间”而非笼统“生效时间” |
| P1 | 审批记录仅按版本号查询 | 不同固件标识存在相同尾号时可能串记录 | 使用固件标识、版本号和流程标识联合关联；界面不展示内部流程标识 |
| P1 | 详情只展示 APP 文案修订，没有展示通用版本编辑修订 | recordVersion 已递增但用户无法查看修改历史 | 新增“版本修订记录”，统一展示普通编辑与 APP 文案修订，区分修订类型、操作人、时间和原因 |
| P1 | 基础信息缺少文件名、MD5、更新时间、修订号和关联设备数 | 无法核对制品完整性、最新修改和发布影响范围 | 补充文件名、MD5、最后更新时间、记录版本 Rn、关联设备数；保留创建人和创建时间 |
| P1 | 下载地址只有复制入口 | 用户仍需复制后再访问 | 同时提供复制和直接下载两个图标操作，并保持与当前发布版本卡片一致 |
| P2 | 版本号在顶部标题和基础信息中重复 | 占用详情首屏空间 | 顶部保留版本号，基础信息移除重复版本号 |
| P2 | “历史功能集快照”单独占用页签，空状态内容高度过大 | 已移出本期新增编辑流程的旧数据持续占用主导航 | 合并到“功能配置”底部的“历史数据”折叠区，仅有历史快照时展示并明确只读 |
| P2 | 功能点“来源状态”容易被理解为发布时快照状态 | 当前源状态与历史快照混淆 | 改名为“当前源状态”，发布时冻结的功能版本和说明独立展示 |
| P2 | 详情规则仍描述“六类页签”，当前页面最多五类 | 需求批注与实际页面不一致 | 更新为四个核心页签，规则数量与页面保持一致 |

## 4. 建议的信息架构

顶部摘要只保留：版本号、版本状态、适用机型、关联设备数、最近生效时间。

基础信息保留：固件标识、文件名、文件大小、MD5、创建人、创建时间、最后更新时间、记录版本、下载操作。

详情收敛为四个页签：

1. 功能配置：展示发布时冻结的功能点快照；旧功能集只读数据作为折叠区。
2. APP 更新说明：只展示最终生效文案和英文兜底，不展示编辑态 AI 草稿过程。
3. 发布与审批记录：按一次业务流程合并发布、回滚、下架、重新发布及审批结果，不展示内部标识。
4. 版本修订记录：展示普通版本编辑和 APP 文案修订的完整审计。

## 5. 状态展示口径

| 状态 | 时间字段 | 提醒方式 | 允许操作 |
| --- | --- | --- | --- |
| 当前发布 | 最近生效时间 | 最近一次生效策略 | 详情、维护 APP 文案、回滚、下架 |
| 未发布 | 未生效 | 发布时配置 | 详情、编辑、发布、删除 |
| 历史发布 | 最近生效时间 | 最近一次生效策略 | 详情、编辑、重新发布 |
| 已回滚 | 最近生效时间、回滚时间 | 最近一次生效策略 | 详情、编辑、重新发布 |
| 已下架 | 最近生效时间、下架时间 | 最近一次生效策略 | 详情、编辑、重新发布 |

## 6. 实施顺序

1. 先统一事件与审批数据关联、动作模板和状态术语，修复逻辑错误。
2. 再调整四页签信息架构，补齐基础字段和版本修订记录。
3. 最后补齐当前版本 Mock 快照，回归发布、回滚、下架、重新发布和编辑链路。
