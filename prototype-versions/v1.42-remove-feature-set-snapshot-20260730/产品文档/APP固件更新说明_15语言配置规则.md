# APP 固件更新说明 15 语言配置规则

## 1. 适用范围

本文档自 2026-07-23 起作为 APP 固件版本更新说明的现行语言规则。其他文档中关于“九种默认语言”“添加扩展语言”或 `zh-CN`、`en-US` 作为新数据存储码的描述停止适用；历史审批快照不追溯改写。

## 3. 交互与数据规则

1. 左侧按固定顺序展示全部 15 种语言并支持纵向滚动，不提供添加或删除语言。
2. 简体中文和英文固定必填；其他语言可为空，并实时显示“未配置”或“已配置”。
3. 顶部显示“已配置 X / 15”；输入与清空内容时即时更新。
4. 空的选填语言不写入版本数据，也不进入新提交的审批快照。
5. APP 请求未配置的选填语言时使用英文说明兜底；预览器允许切换全部 15 种语言，并明确标识英文兜底。
6. 新提交的审批快照只保存提交时实际配置的语言；已存在的历史审批快照保持不可变。
7. 不允许 HTML 或脚本内容，本期不提供自动翻译。

## 4. 兼容规则

| 历史语言码或 APP 环境值 | 统一语言码 |
| --- | --- |
| `zh-CN`、`zh-Hans`、`zh-SG` | `zh` |
| `zh-TW`、`zh-HK`、`zh-Hant`、`zh_FT` | `zh_FT` |
| `en-US`、`en-*` | `en` |
| `it-IT`、`ko-KR`、`de-DE`、`ja-JP`、`fr-FR`、`ru-RU`、`es-ES` | 对应双字母语言码 |
| `pt-BR`、`pt-PT`、`pt-*` | `pt` |

`zh_FT` 为当前 APP 已确认的业务语言码，大小写与下划线按该值保留。若 APP 后续改为标准 BCP 47 语言标签，需要先完成接口契约和历史数据兼容评审。

## 5. 闭环校验

- 创建或编辑版本：缺少 `zh` 或 `en` 时阻止保存，并定位到首个错误语言。
- 发起发布或回滚：再次确认目标版本存在有效 `zh`、`en`，且所有已配置语言未超限。
- APP 预览：配置语言展示自身内容，未配置选填语言展示英文内容并标识“英文兜底”。
- 审批通过：按审批快照执行，不读取审批期间可能变化的实时文案。
- 历史追溯：版本详情展示实际保存语言；历史审批日志继续展示原快照语言码。
